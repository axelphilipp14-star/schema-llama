# AN-004 — Heures du journal de progression inventées

- **Date** : 2026-11-24 (18:20) · **Phase** : C
- **Symptôme** : en générant la note de suivi Obsidian, l'heure réelle (24/11 18:16) contredisait `docs/PROGRESS.md`, qui annonçait des étapes à 19:30, 21:30, 23:00 et « 25/11 00:40 ». La ligne M3 du Journal du projet dans le coffre était datée du 25/11.
- **Cause immédiate** : les heures des entrées ont été écrites de tête, en estimant le temps écoulé, au lieu d'être lues sur l'horloge.
- **5 pourquoi** :
  1. Pourquoi des heures fausses ? Elles n'ont pas été mesurées.
  2. Pourquoi ? Aucune commande ne fournissait l'heure au moment d'écrire l'entrée.
  3. Pourquoi l'erreur n'a-t-elle pas été vue ? Rien ne comparait le journal à une horloge (git, `date`).
  4. Pourquoi est-ce grave ? Un journal horodaté sert de preuve ; une heure inventée est une donnée fabriquée, même sans enjeu.
  5. **Cause racine (processus)** : une valeur présentée comme une mesure (l'heure) n'avait pas d'instrument.
- **Correction** : heures remplacées par l'heure du commit git de chaque étape (`git log`), mention en tête du journal ; date M3 corrigée dans le coffre (25/11 → 24/11).
- **Règle ajoutée** (`CLAUDE.md`) : toute heure écrite vient de `date` ou de `git log`, jamais d'une estimation.
- **Leçon** : même une métadonnée banale est une mesure ; sans instrument, ne pas l'écrire.
